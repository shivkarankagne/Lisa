# Practical OpenCode Zen free models vs Claude Opus 5.5 (research snapshot: 2026-09-24)

## Key Question 1: What does the choice mean for repository changes, tool calls, instructions, and reliability in OpenCode?

### Takeaway

“Free Zen model” is a rotating collection of materially different model/provider endpoints, not one capability tier. A free endpoint can be a good fit for a bounded, testable change, but the available evidence does not show that any current free endpoint is equivalent to Claude Opus 5.5 for difficult repository work; Opus 5.5 is the higher-confidence escalation when a wrong or incomplete multi-step change is expensive. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [OpenCode’s provider metadata](https://models.dev/providers/opencode) [Anthropic’s Opus 5.5 documentation](https://platform.claude.com/docs/en/models/opus-5-5/overview)

### Cited Findings

#### The free catalog is heterogeneous and time-limited

- The prose list on the Zen page names MiMo-V2.6-Flash Free, MiMo-V2.5 Free, Ling 3.0 Flash Fin Free, Nemotron 3 Ultra Free, Nemotron 3.5 Lightning Free, Big Pickle, Space Bunny Free, Muse Spark 1.3 Contributor Free, and Jev 1.13 Free; the page prices the listed free inputs and outputs at `$0` and says the free periods are limited. [OpenCode Zen documentation](https://opencode.ai/docs/zen/)
- The live Zen model endpoint is a more dynamic source than the prose list: when checked on 2026-09-24 it also returned IDs such as `deepseek-v4-flash-free` and `muse-spark-1.2-contributor-free`. This is a reason to check `/models` or the OpenCode picker at the time of use rather than hard-code a permanent “free model” list. [Zen models endpoint](https://opencode.ai/zen/v1/models) [OpenCode Zen documentation](https://opencode.ai/docs/zen/)
- `Jev 1.13 Free` is not a normal text-generating coding agent: Zen describes it as a System One endpoint that evaluates a state against typed questions and returns values/probabilities. The provider catalog reports zero text output and no tool-call capability for Jev. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [OpenCode provider metadata](https://models.dev/providers/opencode)
- `Big Pickle` and `Space Bunny Free` are explicitly described by Zen as “stealth” models. Their public model identity, version history, and reproducible evaluation results are therefore not established by the Zen page. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [OpenCode data: Space Bunny](https://opencode.ai/data/unknown/space-bunny)

The route-specific limits matter more than the base model’s headline context. For example, Xiaomi advertises a 1M-token context for MiMo-V2.6-Flash, while the OpenCode Zen free route is cataloged at 200K input and 32K output. [Xiaomi MiMo model page](https://mimo.mi.com/models/en-US/mimo-v2.6-flash) [OpenCode provider metadata](https://models.dev/providers/opencode)

#### Repository changes are a tool-loop problem, not just a code-generation problem

- OpenCode’s built-in tools include `read`, `grep`, `glob`, `edit`, `write`, `bash`, `apply_patch`, `todowrite`, `webfetch`, `websearch`, `question`, and `skill`; by default the tools are enabled, and the permission system can require approval or deny them. [OpenCode Tools documentation](https://opencode.ai/docs/tools/)
- OpenCode’s built-in Build agent has full tool access, Plan is intended for analysis without making changes and asks before edits and shell commands, and Explore/Scout are read-only research agents. This makes a two-stage workflow—read/plan, then constrained build—practical for comparing models. [OpenCode Agents documentation](https://opencode.ai/docs/agents/)
- Project instructions can be placed in `AGENTS.md`; OpenCode’s `/init` is designed to capture build, lint, test, architecture, and repository-specific conventions. A model that follows these instructions reliably can therefore be more useful than a model with a higher isolated benchmark score but weaker adherence to local workflow rules. [OpenCode Rules documentation](https://opencode.ai/docs/rules/)
- OpenCode says it tested model/provider combinations, worked with providers to serve models correctly, and benchmarked the combinations it recommends. That is evidence of curation effort, not an independent guarantee that every model has equal reasoning or tool-use reliability. [OpenCode Zen documentation](https://opencode.ai/docs/zen/)

The API surface also differs by model. Zen routes most free models through OpenAI-compatible chat completions, routes Opus through the Anthropic Messages API, routes Muse Spark through an OpenAI Responses endpoint, and routes Jev through System One. That means adapter behavior, tool-call parsing, streaming semantics, and provider-specific options are part of the practical model comparison. [OpenCode Zen endpoints](https://opencode.ai/docs/zen/#endpoints)

A catalog’s `Tool Call: Yes` flag should be treated as a smoke-test result, not a success-rate measurement. OpenCode itself warns that only some models are good at both generating code and tool calling, and its provider documentation recommends selecting a model with strong tool-calling support when local tool calls fail. [OpenCode Models documentation](https://opencode.ai/docs/models/) [OpenCode Providers documentation](https://opencode.ai/docs/providers/)

There is a concrete serving-stack example: NVIDIA’s Nemotron model card says that, with SGLang, particular chat-template parameters are required to parse reasoning and tool calls correctly. The same base model can therefore behave differently under different inference servers or gateway configurations. [NVIDIA Nemotron 3 Ultra model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16)

#### Instruction following and long-running reliability: what is actually documented

- Anthropic describes Opus 5.5 as being built for long-running agentic coding and knowledge work. Its documentation reports a 1M-token context, 128K maximum synchronous output, adaptive thinking, and tool support. [Claude Opus 5.5 model overview](https://platform.claude.com/docs/en/models/opus-5-5/overview)
- Anthropic’s own prompting guide says Opus 5.5 is strongest on multistep work in a real repository, including carrying a change through a large codebase until tests pass, and reports stronger long-running autonomous work and code review than Opus 5. Anthropic also reports clearer communication and better adherence to writing rules, but these are Anthropic test claims, not a controlled OpenCode comparison with the free Zen routes. [Prompting Claude Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5) [Introducing Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5)
- Anthropic’s launch material reports Opus 5.5 scores of 66.4% on Terminal-Bench 4.0, 54.4% on FrontierCode v1.1 Main, and 57.8% on CursorBench 4.0, while explicitly cautioning that benchmark margins are less reliable as a guide to real-world differences at this capability level. [Introducing Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5)
- Xiaomi’s official MiMo-V2.6-Flash model card describes the model as trained across coding, general-agent, visual, and security environments, with a 1M context and tool-oriented agent training. That supports “promising for agent work,” not “equivalent to Opus 5.5.” [MiMo-V2.6-Flash model card](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL)
- NVIDIA describes Nemotron 3 Ultra as post-trained for agent harnesses that plan, call tools, delegate, validate, and recover from errors. Its published benchmark table is a useful model-specific signal, but it does not provide a current apples-to-apples Opus 5.5 comparison. [NVIDIA Nemotron 3 Ultra technical blog](https://developer.nvidia.com/blog/nvidia-nemotron-3-ultra-powers-faster-more-efficient-reasoning-for-long-running-agents/) [NVIDIA Nemotron 3 Ultra model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16)
- OpenCode’s usage data shows substantial observed use for models such as MiMo-V2.5 and Nemotron 3 Ultra, but the data page reports token volume, users, retention, cache ratio, and cost—not patch correctness, test-pass rate, invalid tool calls, or instruction violations. Usage is therefore not a quality evaluation. [OpenCode model data](https://opencode.ai/data/) [MiMo-V2.5 data](https://opencode.ai/data/xiaomi/mimo-v2-5) [Nemotron 3 Ultra data](https://opencode.ai/data/nvidia/nemotron-3-ultra)

### Inferences

- For a small repository edit, a free model with a working tool adapter can be operationally sufficient if the task is constrained, the diff is small, and a targeted test plus human review is mandatory. This is a workflow recommendation based on the $0 Zen pricing and OpenCode’s permission/tool model, not evidence that the free model matches Opus. [OpenCode Zen pricing](https://opencode.ai/docs/zen/#pricing) [OpenCode permissions](https://opencode.ai/docs/permissions/)
- A model that can emit a syntactically valid tool call but chooses the wrong file, omits a test, loops after a failed command, or ignores `AGENTS.md` can be worse for repository work than a slower model with better sequencing. The free-model metadata does not measure those behaviors. [OpenCode Tools documentation](https://opencode.ai/docs/tools/) [OpenCode Rules documentation](https://opencode.ai/docs/rules/) [OpenCode provider metadata](https://models.dev/providers/opencode)
- Treat Opus 5.5 as the higher-confidence choice when a failure would require expensive debugging, a security review, a broad migration, or a rollback. This follows Anthropic’s reported long-running coding and repository-work evidence, but it is not a claim that Opus wins every task. [Anthropic Opus 5.5 prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)
- A hybrid session should normally start fresh when switching between a free route and Opus. The routes use different API/tool formats, and Anthropic’s direct API has model-bound thinking blocks and model-specific tool behavior; a route switch can otherwise create a confusing handoff. [OpenCode Zen endpoints](https://opencode.ai/docs/zen/#endpoints) [Opus 5.5 behavior changes](https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5)

### Gaps

- I found no current primary-source evaluation that runs the same OpenCode version, agent prompts, repository snapshots, permissions, tool schemas, provider settings, and task set across all current Zen free IDs and Opus 5.5. Anthropic’s published Opus table and Xiaomi’s/NVIDIA’s model tables use different comparators and harnesses. [Anthropic Opus 5.5 benchmarks](https://www.anthropic.com/claude-opus-5-5) [MiMo-V2.6-Flash model card](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL) [NVIDIA Nemotron 3 Ultra model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16)
- The public identity/version history and reproducible evaluation of Big Pickle and Space Bunny are not available in the cited OpenCode documentation; the Space Bunny data page itself reports context and output as unknown. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [OpenCode data: Space Bunny](https://opencode.ai/data/unknown/space-bunny)
- The catalog metadata does not establish how often a free route emits malformed calls, fails to recover from tool errors, ignores instructions, or silently truncates context. A local smoke test and repository-specific evaluation are still required. [OpenCode provider metadata](https://models.dev/providers/opencode) [OpenCode Tools documentation](https://opencode.ai/docs/tools/)

## Key Question 2: What are the practical speed, rate-limit, availability, privacy, and cost tradeoffs?

### Takeaway

Free Zen usage removes the listed token price but exchanges it for quota uncertainty, limited-time availability, possible privacy exceptions, and potentially more rework. Opus 5.5 has a published price, model lifecycle, direct-API limits, and extensive integration documentation, but it still has spend limits, rate limits, and route-specific retention; neither side is “free” in total workflow cost. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [Claude Opus 5.5 pricing and rate limits](https://platform.claude.com/docs/en/api/rate-limits) [Anthropic API retention documentation](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)

### Cited Findings

#### Rate limits and availability

- The Zen page says the free models are available for a limited time and lists their token prices as free, but the retrieved public Zen documentation does not publish a stable per-model numeric free quota or an SLA. The live `/zen/v1/models` endpoint is therefore more useful for checking whether a model is currently exposed than the prose list. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [Zen models endpoint](https://opencode.ai/zen/v1/models)
- An open OpenCode issue reports users receiving HTTP 429/`FreeUsageLimitError` at an approximately 200-request free cap, including accounts with a Zen balance. This is a user report, not a published quota policy or a confirmed universal limit; it is useful evidence that a free route can interrupt a long session and that the exact cap may depend on account, model, headers, or current backend policy. [OpenCode issue #33495](https://github.com/anomalyco/opencode/issues/33495)
- Opus 5.5 is listed as an active model released on 2026-09-22, with availability through the Claude API, Amazon Bedrock, Google Cloud, Microsoft Foundry, and Claude Platform on AWS; Anthropic says it will not retire sooner than 2027-09-22. This is a more stable documented lifecycle than the free models’ limited-time offers, although it is not an uptime guarantee. [Claude Opus 5.5 model overview](https://platform.claude.com/docs/en/models/opus-5-5/overview)
- Direct Claude API limits are account-tier dependent. The published Start-tier limits for Opus 5.5 are 1,000 requests/minute, 2M input tokens/minute, and 400K output tokens/minute; Build and Scale tiers have higher limits, while new organizations can begin in a lower Evaluation tier. Limits are enforced per organization/model and are not guaranteed minimum capacity. [Anthropic API rate limits](https://platform.claude.com/docs/en/api/rate-limits)
- If Opus is used through Zen rather than directly with Anthropic, Zen’s spend limits, balance, provider routing, and gateway behavior apply; the direct Anthropic tier table should not be presented as a guaranteed Zen quota. Zen’s documentation says a workspace can have a monthly spend limit, and auto-reload can still charge after the balance falls below `$5`. [OpenCode Zen documentation](https://opencode.ai/docs/zen/#monthly-limits)
- OpenCode’s provider documentation says Anthropic prohibits using Claude Pro/Max consumer subscriptions in OpenCode and that prior subscription plugins were removed. A user choosing Opus in OpenCode should therefore plan for an API key or an approved cloud-provider path rather than assume a consumer subscription is a valid OpenCode backend. [OpenCode Providers documentation](https://opencode.ai/docs/providers/)

#### Latency and throughput

- Anthropic classifies Opus 5.5 as moderate comparative latency and reports that it generates output more than 30% faster than Opus 5. Actual latency still depends on prompt length, output length, and thinking effort. [Claude Opus 5.5 model overview](https://platform.claude.com/docs/en/models/opus-5-5/overview)
- Opus 5.5 effort is a practical latency/cost control: `low` is intended for simpler or latency-sensitive work, `medium` is the default balance, and `high`/`xhigh` are for more demanding agentic work. Effort affects tool calls as well as prose, so a lower setting can reduce both token cost and the number of exploratory calls. [Anthropic effort documentation](https://platform.claude.com/docs/en/build-with-claude/effort)
- Anthropic’s fast mode is a research preview on the Claude API only, offers up to 2.5x higher output tokens per second rather than faster time-to-first-token, costs `$8` input and `$40` output per million tokens for Opus 5.5, and has separate rate limits. [Anthropic fast mode](https://platform.claude.com/docs/en/build-with-claude/fast-mode) [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Free-model vendors publish claims that cannot automatically be transferred to Zen. Xiaomi describes MiMo-V2.6-Flash as suitable for high-frequency calls and publishes direct-API limits of 100 RPM and 10M TPM; NVIDIA reports Nemotron 3 Ultra throughput advantages under particular 8K-input/64K-output serving conditions. These are provider/API results, not measured Zen route latency. [Xiaomi MiMo model page](https://mimo.mi.com/models/en-US/mimo-v2.6-flash) [NVIDIA Nemotron 3 Ultra technical blog](https://developer.nvidia.com/blog/nvidia-nemotron-3-ultra-powers-faster-more-efficient-reasoning-for-long-running-agents/)
- I found no current apples-to-apples Zen measurement of p50/p95 time-to-first-token, time-to-first-tool-call, time-to-green, queueing, or 429 rate for the free IDs versus Opus 5.5. The provider metadata and vendor throughput claims do not fill that gap. [OpenCode model data](https://opencode.ai/data/) [OpenCode provider metadata](https://models.dev/providers/opencode)

#### Privacy and data handling

- OpenCode says it does not store code or context data; processing happens locally or through direct calls to the selected provider. The documented exception is `/share`, which sends conversation data to OpenCode’s sharing service, so sensitive trials should disable sharing. [OpenCode Enterprise data handling](https://opencode.ai/docs/enterprise/)
- Zen says its models are hosted in the US and that providers generally follow zero-retention/no-training policies, but it lists material exceptions. Big Pickle, MiMo-V2.5, MiMo-V2.6-Flash, and Ling may use collected data to improve the model during their free periods; Nemotron free endpoints are trial endpoints that log use for security and product improvement and explicitly say not to submit personal or confidential data; Muse Spark Contributor permits use of prompts/completions to train future Meta models. Space Bunny is explicitly called out as following zero-retention and no training. [OpenCode Zen privacy section](https://opencode.ai/docs/zen/#privacy)
- Zen’s privacy table says Anthropic API requests are retained for 30 days under Anthropic’s data policies. That is a different claim from Anthropic’s direct commercial API, where standard API inputs/outputs are generally deleted within 30 days and qualified organizations can request zero data retention (ZDR). Do not infer that an Opus request routed through Zen has the same ZDR terms as a direct Anthropic API organization. [OpenCode Zen privacy section](https://opencode.ai/docs/zen/#privacy) [Anthropic commercial retention policy](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data) [Anthropic ZDR scope](https://privacy.claude.com/en/articles/8956058-i-have-a-zero-data-retention-agreement-with-anthropic-what-products-does-it-apply-to)
- Anthropic’s commercial terms say customer content is not used to train Anthropic models, but the API retention policy still allows 30-day standard retention, longer retention for policy/legal needs, and ZDR only where enabled. [Anthropic Commercial Terms](https://www.anthropic.com/legal/commercial-terms) [Anthropic API retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)
- A model’s data policy does not cover every tool in an OpenCode session. Web fetching, MCP servers, external documentation tools, and other third-party integrations can receive repository content under their own policies; Anthropic explicitly says ZDR does not cover third-party integrations. [Anthropic API and data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention) [OpenCode Tools documentation](https://opencode.ai/docs/tools/)

#### Direct token-cost tradeoff

- Zen’s current price table lists Opus 5.5 at `$4` per million input tokens, `$20` per million output tokens, `$0.20` per million cached reads, and `$5` per million 5-minute cache writes. The free models are listed at `$0` for input, output, and cached reads. [OpenCode Zen pricing](https://opencode.ai/docs/zen/#pricing)
- A simple uncached illustration using the published Opus rates is `1M input + 100K output = $4 + $2 = $6` for one request. If the entire 1M input is written to a 5-minute cache, the first request adds the `$5/M` cache-write charge; a later request that reads the cache would be approximately `$0.20 + $2 = $2.20` before tool-specific or other charges. [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) [OpenCode Zen pricing](https://opencode.ai/docs/zen/#pricing)
- Tool definitions, tool-call blocks, and tool results add tokens to the bill; Anthropic lists 286 automatic tool-use system-prompt tokens for Opus 5.5 when tools are supplied, and tool results are themselves input on subsequent turns. Long coding sessions can therefore cost more than a single user-prompt estimate suggests. [Anthropic pricing: tool use](https://platform.claude.com/docs/en/about-claude/pricing#tool-use-pricing)
- The practical free-model saving is therefore not automatically `$X` in total: it is the listed token charge, while the possible replacement costs are waiting for quota resets, retrying after 429s, re-running failed edits, reviewing larger diffs, and escalating to a paid model after a failure. This is an inference from the free/paid pricing and availability differences, not a measured total-cost study. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [OpenCode issue #33495](https://github.com/anomalyco/opencode/issues/33495)

### Inferences

- For short interactive edits, a free route may win on direct cost and may feel fast; for a long task, a quota interruption can cost more wall-clock time than the Opus token bill. The right comparison is expected cost per successfully completed, tested change, not price per million tokens. [OpenCode Zen pricing](https://opencode.ai/docs/zen/#pricing) [OpenCode Agents documentation](https://opencode.ai/docs/agents/)
- If latency matters, measure the actual Zen route rather than infer it from a base model’s advertised throughput. Opus effort and fast mode provide explicit controls, but fast mode’s premium price and separate limits can erase its value on routine edits. [Anthropic effort documentation](https://platform.claude.com/docs/en/build-with-claude/effort) [Anthropic fast mode](https://platform.claude.com/docs/en/build-with-claude/fast-mode)
- For proprietary source code, the safe default is not “free until proven otherwise.” Avoid free routes with the listed training or trial exceptions; use a direct commercial Anthropic arrangement with appropriate ZDR/contract terms or an approved internal gateway, and separately review MCP/web-tool data flows. [OpenCode Zen privacy section](https://opencode.ai/docs/zen/#privacy) [Anthropic ZDR scope](https://privacy.claude.com/en/articles/8956058-i-have-a-zero-data-retention-agreement-with-anthropic-what-products-does-it-apply-to)
- Set an explicit monthly spend limit, disable or carefully configure Zen auto-reload, and keep a paid fallback budget for tasks that exceed free quotas. Zen documents both monthly limits and the auto-reload caveat. [OpenCode Zen monthly limits](https://opencode.ai/docs/zen/#monthly-limits)

### Gaps

- The public Zen documentation does not establish a stable numeric free quota, reset window, priority queue, or SLA for each free model. The approximately 200-request report is anecdotal and may not describe the current backend. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [OpenCode issue #33495](https://github.com/anomalyco/opencode/issues/33495)
- Direct Anthropic API rate limits do not automatically describe Zen’s Opus route, Bedrock/Vertex limits, or a consumer subscription route. The exact account and provider contract must be checked. [Anthropic API rate limits](https://platform.claude.com/docs/en/api/rate-limits) [OpenCode Zen documentation](https://opencode.ai/docs/zen/)
- No source found provides comparable current p50/p95 latency, queue time, error rate, or retry statistics for the Zen free endpoints and Opus 5.5. [OpenCode model data](https://opencode.ai/data/) [OpenCode provider metadata](https://models.dev/providers/opencode)
- “Zero retention” does not mean “the model never sees the data,” and it does not cover third-party tools. The exact contract and tool graph must be reviewed for sensitive work. [Anthropic API and data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention) [OpenCode Tools documentation](https://opencode.ai/docs/tools/)

## Key Question 3: Which model should be used for each task, and why can benchmark quality differ from workflow quality?

### Takeaway

Use a risk-based hybrid workflow: free Zen models first for disposable, bounded, easily tested work; Claude Opus 5.5 for difficult debugging, architecture, security-sensitive reasoning, and long refactors; and a local task-specific evaluation to decide which free endpoint is safe for a given repository. This is a recommendation grounded in the documented capabilities and workflow mechanics, not a claim that any free model is equivalent to Opus. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [OpenCode Tools and Agents documentation](https://opencode.ai/docs/tools/) [Opus 5.5 model overview](https://platform.claude.com/docs/en/models/opus-5-5/overview)

### Cited Findings

#### Task-based recommendations

| Task | Practical default | Why and guardrail |
|---|---|---|
| **Quick edits**: rename, add a log, adjust a test, update a small function | Try a current free tool-call model first; examples in the catalog include MiMo-V2.6-Flash Free and Nemotron 3.5 Lightning Free, but the catalog does not rank them for this task. Require a small diff, targeted tests, and human review. | Free routes are `$0` in Zen’s price table and most named free models advertise tool calling, but tool-call support is not a success-rate guarantee. Use `edit: ask`/deny rules and inspect the diff. [OpenCode Zen pricing](https://opencode.ai/docs/zen/#pricing) [OpenCode provider metadata](https://models.dev/providers/opencode) [OpenCode permissions](https://opencode.ai/docs/permissions/) |
| **Everyday coding**: feature work across a few files, API glue, documentation, test additions | A free model is reasonable when the task has explicit acceptance criteria and deterministic tests. #### Why benchmark quality is not workflow quality

- Anthropic’s Opus 5.5 benchmark table is useful evidence of strong agentic coding, but Anthropic itself says benchmark margins become less reliable as a guide to real-world differences at the frontier. The reported Opus 5.5 results also use model-specific effort settings, production safeguards, and sometimes fallback models; those conditions are part of the result, not footnotes to ignore. [Introducing Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5) [Opus 5.5 behavior changes](https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5)
- Xiaomi’s own MiMo-V2.6-Flash table reports 67.9 on DeepSWE, 61.2 on MiMo Code Bench, 73.6 on Toolathlon Verified, and 28.8 on Terminal-Bench 4.0; the Claude comparator in that table is Claude Opus 5, with 74.0, 68.6, 80.6, and 49.0 respectively. This is a useful example of a free-family model being competitive on some dimensions and behind on others, but it is not a comparison with Opus 5.5 and it is not a measurement of the capped Zen free route. [MiMo-V2.6-Flash model card](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL)
- NVIDIA’s Nemotron 3 Ultra material reports 54% on Terminal-Bench 2.0, 82% on IFBench, and 95% on RULER at 1M, but it compares against other open models rather than Opus 5.5. These numbers cannot settle the free-versus-Opus choice. [NVIDIA Nemotron 3 Ultra technical blog](https://developer.nvidia.com/blog/nvidia-nemotron-3-ultra-powers-faster-more-efficient-reasoning-for-long-running-agents/) [NVIDIA Nemotron 3 Ultra model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16)
- OpenCode’s benchmark explanation highlights another source of variation: the same model/provider can be configured differently, and OpenCode says it benchmarks the model/provider combination rather than only the base model. Tool-call parsing, quantization, context caps, caching, and server implementation can change observed behavior. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [NVIDIA Nemotron model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16)
- A larger context window is not automatically better. Anthropic’s context documentation calls out “context rot”: accuracy and recall can degrade as token count grows, so curating relevant state, checkpointing, and compaction matter. [Anthropic context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)
- OpenCode Bench is a more workflow-shaped example: it derives tasks from production commits, runs three isolated episodes with fresh repository clones, imposes a 30-minute agent timeout, and scores API signatures, logic equivalence, integration correctness, test coverage, and project checks with multiple judges. That is still an evaluation harness, not a guarantee of production reliability, but it measures more of the repository loop than a single answer-quality score. [OpenCode Bench repository](https://github.com/anomalyco/opencode-bench)
- A fair local comparison should hold the OpenCode version, agent prompt, repository snapshot, permissions, tool schemas, provider settings, temperature/effort, and timeout constant; run multiple fresh-clone trials; and record at least: patch/test success, hidden-test pass rate, invalid or redundant tool calls, recovery after tool failure, instruction/permission violations, time-to-green, p50/p95 latency, tokens, cache ratio, retries, 429s, and total cost. This follows the production-commit and multi-episode structure documented by OpenCode Bench and the effort/context cautions in Anthropic’s docs. [OpenCode Bench repository](https://github.com/anomalyco/opencode-bench) [Anthropic effort documentation](https://platform.claude.com/docs/en/build-with-claude/effort) [Anthropic context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)

### Inferences

- Benchmark quality is best treated as a screening signal. Workflow quality is a vector: successful patch rate, instruction adherence, tool-loop recovery, time-to-green, quota interruptions, privacy, and total cost all matter. A model can be the better benchmark performer yet the worse operational choice if it needs more retries, overruns the context, or is unavailable when needed. [OpenCode Bench repository](https://github.com/anomalyco/opencode-bench) [Anthropic Opus 5.5 launch material](https://www.anthropic.com/claude-opus-5-5)
- The strongest practical policy is escalation rather than a permanent single-model choice: run a cheap/free model for discovery and bounded implementation, then invoke Opus when the task crosses a defined risk threshold such as multi-module changes, unclear root cause, security impact, architectural coupling, or a failed test/review loop. This policy is consistent with OpenCode’s separate Plan/Build/Explore agents and with Anthropic’s reported long-running coding evidence. [OpenCode Agents documentation](https://opencode.ai/docs/agents/) [Anthropic Opus 5.5 prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)
- Do not describe a free model as “Opus-equivalent” unless the same repository-specific evaluation demonstrates that claim at the required success, latency, privacy, and availability thresholds. The current primary sources support “some free models are strong at particular agent/coding tasks,” not universal equivalence. [MiMo model card](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL) [NVIDIA model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16) [Anthropic Opus 5.5 launch material](https://www.anthropic.com/claude-opus-5-5)

### Gaps

- There is no current, independent, apples-to-apples OpenCode workflow benchmark covering every named free Zen ID and Opus 5.5. The available benchmark tables use different model versions, providers, harnesses, effort settings, and task suites. [OpenCode Bench repository](https://github.com/anomalyco/opencode-bench) [MiMo model card](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL) [NVIDIA model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16)
- No public source establishes how often the current free Zen routes ignore `AGENTS.md`, produce invalid tool calls, fail to recover from a failed command, or make unrelated edits. These must be measured in the user’s own repository. [OpenCode Rules documentation](https://opencode.ai/docs/rules/) [OpenCode Tools documentation](https://opencode.ai/docs/tools/)
- The public Zen materials do not provide stable p50/p95 latency, queue, or quota data, and the stealth models do not provide a stable public identity for independent reproduction. [OpenCode Zen documentation](https://opencode.ai/docs/zen/) [OpenCode issue #33495](https://github.com/anomalyco/opencode/issues/33495)
- A final model choice should therefore be validated with a small, representative OpenCode evaluation and revisited when the Zen catalog, provider route, or model version changes.
